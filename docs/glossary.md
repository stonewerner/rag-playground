# Glossary

Terms as this project uses them. Where a term is overloaded elsewhere, the project meaning wins.

| Term                              | Meaning here                                                                                                                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Abstain**                       | (Phase 3) The generator explicitly declines to answer because the retrieved context does not support an answer. Scored against `unanswerable` gold questions.                              |
| **Alpha (α)**                     | Hybrid fusion weight in [0, 1]. α = 1 is dense-only order, α = 0 is sparse-only order. Applied to RRF contributions, not raw scores (architecture §12.4). Tuned on the dev split only.     |
| **Candidate pool / `candidateK`** | How many hits each retriever (dense, sparse) returns before fusion and reranking. Every candidate is stored on the run.                                                                    |
| **Chunk**                         | A contiguous span `[start_char, end_char)` of a document's normalized text, produced by a chunker under one index config, plus the exact text that was embedded.                           |
| **Chunker**                       | A hand-written function that splits normalized text into chunks: `fixed_token`, `recursive`, `heading_aware` (semantic is parked). Versioned via `chunkerVersion`.                         |
| **Contextual chunk header**       | (Phase 4) Document title and heading path prepended to the embedded text of a chunk. Changes the embedding, not the span.                                                                  |
| **Corpus**                        | A set of documents. The EDGAR corpus is shared and read-only; each guest may have one private corpus. Gold sets belong to a corpus.                                                        |
| **Coverage `cov(c, g)`**          | Fraction of gold span g's characters that chunk c overlaps: overlap(c, g) ÷ length(g). Defined in architecture §11.                                                                        |
| **Coarse span**                   | A gold span stored as a whole chunk because the labeler did not highlight the evidence. Flagged `is_coarse`; excluded from the curated benchmark.                                          |
| **Dense retrieval**               | Nearest-neighbor search over embedding vectors (cosine similarity) in the Pinecone dense index.                                                                                            |
| **Dev / test split**              | Partition of the gold set. Knobs (e.g. alpha) are tuned on dev; headline numbers are reported on test only.                                                                                |
| **Document**                      | An uploaded or preloaded file after normalization to markdown. Immutable; identified by content hash within a corpus.                                                                      |
| **EDGAR**                         | The SEC's filing system. Our shared corpus is a few 10-K annual reports fetched from it and normalized to markdown.                                                                        |
| **Estimated cost**                | List-price dollar cost of a run's vendor calls (embedding tokens, rerank requests, read units, LLM tokens) from the versioned price table. An estimate, not a bill.                        |
| **Faithfulness**                  | (Phase 3) Share of an answer's claims that are supported by the cited retrieved context, as scored by the LLM judge.                                                                       |
| **Citation correctness**          | (Phase 3) Share of citations whose cited chunk actually supports the sentence it is attached to.                                                                                           |
| **Fusion**                        | Combining the dense and sparse ranked lists into one ranking. Ours is weighted RRF, written by hand.                                                                                       |
| **Gold question**                 | A question in a gold set, with type, split, optional reference answer, and gold spans.                                                                                                     |
| **Gold set**                      | The labeled questions for one corpus. The curated EDGAR gold set is versioned fixtures (`fixtures/gold/`). Guest labels form session-scoped sets.                                          |
| **Gold span**                     | A relevance label anchored to source text: `(document_id, start_char, end_char, grade)`. Config-independent, which is what makes cross-config metrics valid.                               |
| **Grade**                         | Relevance level of a gold span: 0 judged not relevant, 1 relevant, 2 highly relevant. Binary metrics treat grade ≥ 1 as relevant.                                                          |
| **Heading path**                  | The chain of markdown headings above a chunk (e.g. `["Item 7. MD&A", "Liquidity"]`).                                                                                                       |
| **Hybrid search**                 | Dense + sparse retrieval fused with RRF.                                                                                                                                                   |
| **Index config**                  | An immutable recipe of ingestion-time knobs (chunker, size, overlap, embedding model and dims, contextual headers) applied to one corpus. Owns one Pinecone namespace. First-class object. |
| **Ingestion job**                 | The resumable unit of work that chunks, embeds, and upserts one document under one index config.                                                                                           |
| **Ingestion-time knob**           | A setting that changes what is stored; changing it means a new index config and re-embedding.                                                                                              |
| **judged@k**                      | Share of the top-k results that overlap any judged span (grade ≥ 0). Low values mean metrics rest on unjudged results.                                                                     |
| **MRR (MRR@k)**                   | Mean over questions of 1 / rank of the first relevant result within the top k (0 if none).                                                                                                 |
| **Namespace**                     | A partition inside a Pinecone index. Ours: `cfg-<index_config_uuid>`, one per index config, in both dense and sparse indexes.                                                              |
| **nDCG@k**                        | Normalized discounted cumulative gain at k: rewards relevant results near the top, normalized by the ideal ranking. Our headline metric (nDCG@10). Span-dedup rules in architecture §12.   |
| **Normalized text**               | The NFC markdown form of a document with `\n` newlines. All offsets point into it, as UTF-16 code-unit indices.                                                                            |
| **Preset config**                 | An index config on the shared corpus, created by the seed script. Guests can query presets but not add configs to the shared corpus.                                                       |
| **Query config**                  | The query-time knobs of a run: mode, top-k, candidate pool, fusion (alpha, k), rerank (on/off, model, depth), score threshold.                                                             |
| **Query-time knob**               | A setting that changes only how stored vectors are searched and ranked. Never triggers re-embedding.                                                                                       |
| **recall@k**                      | Share of a question's gold spans claimed by results in the top k.                                                                                                                          |
| **Replay**                        | Re-executing a past run's exact snapshot as a new run linked by `replay_of_run_id`, and diffing the results. Viewing a past run makes no external calls.                                   |
| **Rerank**                        | Re-scoring the top `depth` candidates with a cross-encoder (Pinecone-hosted `bge-reranker-v2-m3`) and reordering them.                                                                     |
| **Rerank depth ("rerank top-n")** | How many top candidates are sent to the reranker. Distinct from top-k, which is how many results are returned.                                                                             |
| **Rank movement**                 | The change between a candidate's pre-rerank rank and its post-rerank rank; visualized per run.                                                                                             |
| **RRF (Reciprocal Rank Fusion)**  | Fusion that scores each item by Σ 1 / (k + rank) across ranked lists (k = 60 default). Rank-based, so it needs no score normalization across retrievers. Ours is weighted by alpha.        |
| **Run**                           | One immutable query execution with its full snapshot: configs, query text, every candidate's scores and ranks, latencies, usage, cost, metrics.                                            |
| **Scorecard**                     | Batch-eval output for one (index config, query config) over a gold set split: mean metrics with 95% bootstrap CIs, per-type breakdown, per-question rows.                                  |
| **Session (guest)**               | Anonymous identity from a signed cookie. Owns a private corpus, configs, runs, and labels until TTL cleanup.                                                                               |
| **Sparse retrieval**              | Lexical retrieval over learned sparse vectors produced by Pinecone's hosted `pinecone-sparse-english-v0` in the sparse index.                                                              |
| **Stage latency**                 | Wall-clock milliseconds for one pipeline stage (`embed_query`, `dense_search`, `sparse_search`, `fusion`, `rerank`, `hydrate`, `generation`).                                              |
| **τ (tau)**                       | The coverage threshold for counting a chunk as relevant to a gold span. Default 0.5.                                                                                                       |
| **Top-k**                         | Number of results returned after fusion, threshold, and rerank.                                                                                                                            |
| **TTL cleanup**                   | Daily job that deletes idle guest sessions and everything they own: Pinecone namespaces, blobs, rows.                                                                                      |
